# Progress — 2026-10-24

## Current scope

Training and acceptance use our native **MJLab `ManagerBasedRlEnv`**. The first task is G1 motion tracking with MBDAC, followed by MBDACAMP against the retained AMP+PPO velocity baseline. Other simulator backends are deferred. The standalone learning core imports no simulator SDK.

## Implemented and measured

- Twenty-six checks pass, including gradient isolation, real replay boundaries, physical primitive routing, AMP expert cycling/style gradients/warmup, the exact 10-WM / 1-actor / 20-critic optimizer schedule, checkpoint resume, export, and adapter-owned episode randomization. Twenty-five run without simulator SDKs; the additional expert-loader integration regression uses the optional example module.
- Built and installed the wheel in a separate environment with no MJLab, MuJoCo, Isaac Lab or RSL-RL installed. Actor BPTT, AMP parameter isolation, TensorBoard logging, checkpoint resume and exported actor equivalence passed there.
- Native G1 tracking runs with 1024 real worlds, WM batch 128, actor batch 256, original full network widths, history 10, WM horizon 8 and actor horizon 32. The model fits only real transitions. The first 500 iterations are WM-only, following the supplied reference repository's extra warmup.
- The first 2000 iterations took 2059.69 s (34.33 min) and collected 5,185,536 real transitions. The continuation enables `torch.compile`. Its initial compilation cost is included in cumulative training time; steady collection plus update is approximately 0.54–0.58 s per outer iteration when evaluations are not running concurrently.
- G1 reached checkpoint 5000: cumulative active training time 4023.12 s (67.05 min), with 12,931,072 real transitions. This includes WM warmup, compilation and resumed replay refill. Full-clip physical evaluation completed; these timings cannot be compared directly with a different velocity task.

### AMP training after the MBDAC review

The full-width MBDACAMP velocity run completed 500 WM-only iterations. Compiling
the analytic task's first actor backward then failed in Triton with
`PassManager::run failed`. The process exited; its stable `model_500.pt`, console
trace, and measured 391.72 s process cost are preserved in
`logs/velocity_mbdacamp_1024_v2*`.

The continuation resumes that stable checkpoint with compiled WM dynamics and
ordinary Torch autograd for analytic task heads. At iteration 510, all four
optimizer phases completed with finite values; the first actor backward now
passes. The task/reward formulas and update schedule are unchanged. This confirms
runtime recovery, not gait quality. There are 1024 native MJLab worlds, WM batch
128 and actor batch 256. The launch record includes the earlier failed process
cost so it cannot disappear from the final timing comparison.

Live continuation: [MBDACAMP velocity](https://forge.coreweave.com/wandb/sslab_motion_mimic-teams/mbdac-velocity/runs/0qn25b2s).

The reward audit separates formula reuse from the native one-substep derived-kinematics cache lag. Given identical physical inputs, reward-sum error is 3.73e-9. Imagined smooth gates and current-state analytic FK differ from native hard events/cache timing and are reported separately.

An expert-sampler regression was caught before the velocity learning run: the external loader cycles clips by batch index within a generator. Taking only the first batch from a newly constructed generator would repeatedly select clip 0. The integration now preserves the original 20-batch cycle across updates, and a regression test confirms coverage of all 18 clips. The earlier short AMP smoke runs used the old first-clip sampler; they remain interface checks. G1 MBDAC tracking has no AMP prior and is unaffected.

### First AMP velocity training and physical evaluation

The 2000 checkpoint has 5,251,072 real transitions. Process cost through its saved checkpoint is 1584.04 s including failed compilation, both launches and replay refill. Its actual 20 s evaluations improve from 0/5 survival at 1000 to 5/5 at 1500 and 2000. The 2000 policy still moves forward/turns across commands, with forward XY/yaw RMSE 0.226 m/s / 1.470 rad/s, versus PPO's 0.159 / 0.335. Gait is too rapid and slips. This is not accepted velocity control, and a speed advantage at matched quality remains unproven. See [measured results](velocity_results_2026-10-24.md). Only MBDACAMP receives further long training.
